Step model · screen changes

What changes on screen

Built on the builder prototype (docs/design/builder.html) with its own styles: same bar, rail, canvas cards, decisions and right-hand sheet. Only what is tagged New or Changed differs; everything else is as today. Example: the invoice workflow. Design only; nothing here is wired.

1 · The canvas

  • Rail: as today, with a Steps section on top (the flow kinds) and tools split into Connectors (outside systems) and Areas (our records). Dropping an action still makes a step, now a Do step using it.
  • Cards: same cards; the small line under the name reads done by and what it uses ("AI · Read a document").
  • Outputs sit beside the trigger, as their own card. End replaces Stop and names what it delivers.

3 · A Match step, an End, and the workflow's outputs

  • Match New: what a Do step shows when it uses a Match. The "never the same" rules come from the profile and can't be edited.
  • End New: picks from the workflow's outputs, or Nothing to do with a reason. Added by the builder at the end of every path that doesn't rejoin; filled, not deleted.
  • Outputs New: opens from the Outputs card beside the trigger. Publishing is refused while an output is delivered by no End.

4 · The connector page, and Request an action

  • Actions on or off New: a switch per action on today's connector page. Off means agents can't use it.
  • Request an action New: the same small form from a connector, an agent, or the client's account. It becomes a Dev queue request; a client never sees the word "connector".
